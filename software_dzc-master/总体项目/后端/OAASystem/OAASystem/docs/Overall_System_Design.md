## 系统总体设计

### 1. 系统架构

本系统采用经典的**B/S (Browser/Server) 架构**，实现前后端分离。前端负责用户界面和交互逻辑，通过 HTTP/HTTPS 协议与后端进行数据交互。后端基于 **Spring Boot 框架**构建，提供 RESTful API 接口，处理业务逻辑、数据存储和文件管理。

#### 1.1 逻辑分层

后端服务遵循**三层架构**设计原则，确保模块化、可维护性和可扩展性：

1.  **表现层 (Controller 层):** 负责接收和响应来自前端的 HTTP 请求。它将请求参数映射到 Java 对象，调用 Service 层进行业务处理，并将处理结果封装成 JSON 等格式返回给前端。
2.  **业务逻辑层 (Service 层):** 包含核心业务逻辑。它处理具体的业务规则、数据校验和复杂的业务流程。Service 层协调 Mapper 层进行数据操作，并可能调用其他 Service 层的服务。
3.  **数据持久层 (Mapper 层):** 负责与数据库进行交互。使用 **MyBatis 框架**进行数据持久化，将 Java 对象映射到数据库记录，执行 SQL 查询、插入、更新和删除操作。
4.  **数据实体层 (Pojo 层):** 定义了系统中的数据模型，通常与数据库表结构一一对应。这些 POJO (Plain Old Java Object) 用于在不同层之间传输数据。

### 2. 设计原则

- **高内聚，低耦合:** 各模块内部功能紧密相关 (高内聚)，模块之间依赖关系最小化 (低耦合)，提高系统的可维护性和可测试性。
- **可扩展性:** 系统设计考虑未来功能扩展，通过模块化和接口抽象，方便新功能的集成。
- **安全性:** 考虑用户认证、权限管理和数据传输安全。
- **性能优化:** 针对数据查询和文件操作进行优化，确保系统响应速度。

### 3. 技术栈

- **后端框架:** Spring Boot
- **持久层框架:** MyBatis
- **数据库:** MySQL
- **文件存储:** 本地文件系统 (用于存储图片、视频等)

## 功能设计

本系统根据业务需求划分为以下主要功能模块：

1.  **用户管理模块:**
    - 用户注册、登录、登出。
    - 用户个人信息（昵称、电话、邮箱、性别、头像等）管理及更新。
    - 用户密码重置和修改。
    - 用户画像生成和行为数据记录。
    - 用户列表查询、分页、搜索和导入功能。
    - 用户增长统计。
2.  **租户管理模块:**
    - 租户信息（名称、联系人、电话、管理员账号等）的创建、查询、更新和删除。
    - 租户图标上传。
    - 租户及其关联部门和用户的级联管理。
3.  **部门管理模块:**
    - 部门的创建、查询、更新和删除。
    - 支持部门层级结构（通过路径管理）。
    - 根据不同条件（如租户 ID、部门名称、状态）查询部门。
4.  **会议管理模块:**
    - 会议的创建、查询（所有会议、待审批、已审批、按状态查询）、更新和删除。
    - 会议封面图片上传。
    - 会议审批流程（批准、拒绝）。
    - 会议搜索功能。
5.  **会议回执模块:**
    - 会议回执的提交。
6.  **课程管理模块:**
    - 课程的创建、查询（所有课程、待审批、已审批、按状态查询）、更新和删除。
    - 课程封面图片和视频文件上传。
    - 课程审批流程（批准、拒绝）。
    - 课程搜索功能。
7.  **资讯管理模块:**
    - 系统资讯的发布、查询（按路径前缀、标题、作者、租户 ID、待审批、已审批、按状态查询）、更新和删除。
    - 资讯审批流程。
8.  **系统测试模块:**
    - 提供数据库连接测试接口，用于验证系统与数据库的连通性。
